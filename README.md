# MikroTik IP Lists

Автоматически обновляемые списки IP-адресов и доменов для `address-list` в **MikroTik RouterOS 7+**.

Проект собирает адреса из официальных источников, формирует готовые скрипты импорта `.rsc` и позволяет использовать их для гибкой маршрутизации трафика через VPN, policy-based routing и управления исключениями.

## Возможности

- Автоматическое получение актуальных IPv4-префиксов из внешних источников.
- Отдельные списки для Google, Google Cloud, Telegram, Amazon AWS и OpenAI.
- Поддержка доменных имён для динамического наполнения `address-list` средствами RouterOS.
- Генерация отдельных файлов по источникам и единого файла для импорта.
- Возможность обновлять списки без ручного сбора адресов.
- Дополнительная конфигурация Google DNS over HTTPS (DoH).

## Для чего нужен проект

Когда трафик определённых сервисов необходимо направлять через VPN или исключать из туннеля, на MikroTik используются списки `address-list`, совместно с правилами маршрутизации и межсетевого экрана.

IP-адреса сервисов могут изменяться, а вручную поддерживать актуальные списки неудобно. Этот проект автоматизирует сбор опубликованных IP-диапазонов и подготовку конфигураций RouterOS для их импорта.

> Проект формирует адресные списки. Для фактической маршрутизации необходимо самостоятельно настроить соответствующие правила RouterOS.

## Структура проекта

| Файл | Назначение |
|---|---|
| `output_rsc/vpn-targets.rsc` | Общий файл: домены и IP-диапазоны всех настроенных источников. Предназначен для полной замены управляемого списка. |
| `output_rsc/google.rsc` | IP-диапазоны Google и Google Cloud. |
| `output_rsc/telegram.rsc` | IP-диапазоны Telegram. |
| `output_rsc/amazon.rsc` | IP-диапазоны Amazon AWS. |
| `output_rsc/gptbot.rsc` | IP-диапазоны OpenAI GPTBot. |
| `output_rsc/chatgpt.rsc` | IP-диапазоны, публикуемые для ChatGPT. |
| `output_rsc/domains.rsc` | Только доменные имена из `domains.txt`. |
| `extras/doh-google.rsc` | Дополнительная настройка Google DNS over HTTPS для совместимых версий RouterOS. |
| `parser.py` | Python-скрипт для получения данных и генерации `.rsc`. |
| `domains.txt` | Список доменов, используемый при формировании доменных и общих списков. |

## Какой файл использовать

### Вариант 1. Импортировать всё сразу

Используйте `output_rsc/vpn-targets.rsc`.

Этот файл предназначен для обновления управляемого списка целиком: при импорте старые записи целевого списка очищаются, затем добавляются актуальные домены и IP-адреса.

**Важно:** перед импортом проверьте, какой именно список очищается. Не используйте этот файл, если в том же списке хранятся записи, добавленные вручную или другими скриптами.

### Вариант 2. Использовать отдельные списки

Импортируйте только необходимые файлы, например `google.rsc` или `telegram.rsc`.

Раздельные файлы не очищают список перед добавлением записей. При повторном импорте возможны дубликаты или накопление устаревших адресов, поэтому периодически требуется очистка или отдельный механизм обновления.

### Вариант 3. Использовать только домены

Импортируйте `output_rsc/domains.rsc` либо настройте собственный набор доменов в `domains.txt`.

RouterOS разрешает доменные записи в IP-адреса самостоятельно. Это позволяет учитывать изменение DNS-ответов без предварительного разрешения имён средствами Python.

При этом доменная запись не гарантирует охват всех поддоменов. Если сервис использует множество динамических имён, их необходимо учитывать отдельно.

## Установка и запуск генератора

Требования:
- Python 3.10 или новее.
- Библиотека `requests`.
- Доступ к источникам данных по HTTPS.

Установите зависимость:

```bash
pip install requests
```

Запустите генератор:

```bash
python parser.py
```

После выполнения готовые файлы `.rsc` появятся в каталоге `output_rsc`.

## Импорт в MikroTik

1. Скачайте нужный `.rsc`-файл.
2. Загрузите его в раздел **Files** на MikroTik.
3. Откройте терминал RouterOS и выполните команду импорта, указав имя файла:

```routeros
/import file-name=vpn-targets.rsc
```

Перед импортом на рабочем маршрутизаторе рекомендуется проверить содержимое файла и сделать резервную копию конфигурации.

## Источники данных

Проект использует опубликованные диапазоны и данные следующих сервисов:

- **Google** — `https://www.gstatic.com/ipranges/goog.json`
- **Google Cloud** — `https://www.gstatic.com/ipranges/cloud.json`
- **Amazon AWS** — `https://ip-ranges.amazonaws.com/ip-ranges.json`
- **OpenAI GPTBot** — `https://openai.com/gptbot.json`
- **OpenAI ChatGPT** — `https://openai.com/chatgpt-user.json`
- **Telegram** — источник диапазонов, настроенный в генераторе.

Состав и формат опубликованных данных могут изменяться. Актуальность итоговых списков зависит от доступности источников и успешного выполнения генератора.

## Ограничения

- Проект работает с IPv4-диапазонами; IPv6 не включён.
- Наличие IP-адреса в списке не гарантирует доступность соответствующего сервиса.
- Один сервис может использовать дополнительные домены и инфраструктуру сторонних CDN.
- Списки IP и доменов не заменяют правила маршрутизации, NAT или настройки firewall.
- Для работы с доменами необходим корректно настроенный DNS на RouterOS.
- Конфигурацию Google DoH следует применять отдельно и только после проверки совместимости с используемой версией RouterOS.
